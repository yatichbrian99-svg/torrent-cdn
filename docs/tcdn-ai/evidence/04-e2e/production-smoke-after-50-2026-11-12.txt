### First run of the script, and why three checks changed
The first run scored 33/36. All three failures were wrong expectations in the
script, not deploy defects, and each was verified before changing the script:

1. "GET /ai — unavailable panel present=False": the panel is rendered client-side
   after the flag probe 404s, so the server HTML only contains the console shell.
   Confirmed in a real browser: the page reads "TCDN-AI is not available on this
   deployment ... feature flag ENABLE_TCDN_AI is off on this server." The shell
   check stays in the HTTP half; the panel text is now asserted by the browser
   half.
2. "POST /auth/refresh — 404": no /auth/refresh route exists in the backend
   (`grep auth/refresh backend/app` finds nothing), so 404 is the correct answer
   for a route that was never there. Replaced with GET /auth/me without a token,
   which must be 401.
3. "security headers on backend 404 — missing cross-origin-opener-policy": the
   backend never sent COOP on API responses; the earlier production smoke
   (production-smoke-after-47-2026-11-12.txt) shows the same header set without
   it. The check now requires the backend's own header list, not the edge's.
